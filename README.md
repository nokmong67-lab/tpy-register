# ทะเบียนคุมและติดตามการชำระเงิน — โรงพยาบาลตาพระยา

ระบบทะเบียนคุมหนังสือเรียกเก็บ/แจ้งโอน ทำงานเป็นหน้าเว็บไฟล์เดียว (`index.html`) บน GitHub Pages และเก็บข้อมูลใน Google Sheets ผ่าน Google Apps Script

## ขั้นตอนงาน
1. **รับหนังสือ** บันทึกหนังสือเรียกเก็บ / แจ้งโอน
2. **ตรวจสอบ** พร้อมดาวน์โหลดบันทึกข้อความ (.docx)
3. **ทำหนังสือ** แจ้งโอน หรือส่งใบเสร็จ (ภายนอก/ภายใน) ดาวน์โหลดเป็น .docx
4. **ติดตามใบเสร็จ** ภายใน 30 วัน

มีแดชบอร์ดสรุปยอดเรียกเก็บ/ยอดโอนรายหน่วยบริการ ล็อกอินพร้อมสิทธิ์รายคนต่อขั้นตอน เลือกสีธีมได้ และแสดงวันที่เป็น พ.ศ.

## โครงสร้างไฟล์
| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | หน้าเว็บทั้งหมด (อัปโหลดขึ้น GitHub) |
| `Code.gs` | ตัวเก็บข้อมูล วางใน Apps Script ของ Google Sheet (**ไม่ต้องอัปโหลดขึ้น GitHub**) |

## ติดตั้ง
### 1) Google Sheets + Apps Script
1. สร้างสเปรดชีตใหม่ → **ส่วนขยาย → Apps Script**
2. วางโค้ดจาก `Code.gs` (ใช้ไฟล์เวอร์ชันล่าสุดเท่านั้น) และแก้ `var API_KEY = '...'` เป็นรหัสลับของหน่วยงาน
3. **Deploy → New deployment → Web app** · Execute as: **Me** · Who has access: **Anyone**
4. คัดลอก Web app URL (ลงท้าย `/exec`)

แก้ `Code.gs` ภายหลัง ต้อง Deploy → Manage deployments → New version

### 2) GitHub Pages
1. สร้าง repository (Public) อัปโหลด `index.html` และ `README.md`
2. **Settings → Pages → Deploy from a branch → `main` / root**
3. เปิด `https://<ชื่อ-github>.github.io/<ชื่อ-repo>/`

### 3) ใช้งานครั้งแรก
1. เปิดลิงก์หน้าเว็บ (ถ้ายังไม่ได้ใส่ URL ในไฟล์ ระบบจะถามครั้งเดียว)
2. ระบบให้ตั้งซูเปอร์แอดมินคนแรก (ชื่อผู้ใช้ + รหัสผ่าน) แล้วถามรหัสลับ `API_KEY` ที่ตั้งไว้ใน Code.gs (ใช้ครั้งเดียวตอนนี้เท่านั้น)
3. เมนู **ผู้ใช้งานและสิทธิ์** เพิ่มเจ้าหน้าที่และกำหนดสิทธิ์แต่ละขั้นตอน
4. แจกเฉพาะ **ลิงก์หน้าเว็บ + ชื่อผู้ใช้/รหัสผ่านรายคน** ไม่ต้องแจก API_KEY

## ผู้เยี่ยมชมและผู้ใช้ที่ล็อกอิน
- **ผู้เยี่ยมชม** เปิดลิงก์แล้วดูรายการ แดชบอร์ด และดาวน์โหลดเอกสารได้เลย โดยไม่ต้องล็อกอิน แต่แก้ไขอะไรไม่ได้
- **ผู้ใช้ที่ล็อกอิน** กด “เข้าสู่ระบบเพื่อแก้ไข” ใช้ชื่อผู้ใช้/รหัสผ่านที่ซูเปอร์แอดมินสร้างให้ แก้ไขได้ตามสิทธิ์แต่ละขั้นตอน
- **ซูเปอร์แอดมิน** จัดการผู้ใช้และตั้งค่าได้
- การตรวจสิทธิ์ทำที่ฝั่ง Google (Code.gs) ไม่ใช่แค่ซ่อนปุ่ม ผู้ที่ไม่ได้ล็อกอินจึงเขียนข้อมูลผ่านสคริปต์ไม่ได้

## ความปลอดภัย
- **ห้ามใส่ `API_KEY` ลงใน GitHub** ใช้เฉพาะตอนสร้างซูเปอร์แอดมินคนแรก หลังมีผู้ใช้แล้วรหัสนี้เขียนข้อมูลไม่ได้
- ผู้เยี่ยมชมอ่านรายการ ตั้งค่า (รวมเลขบัญชีที่ใส่ในหน้าตั้งค่า) และบัญชีหน่วยงานได้ จึงไม่ควรใส่ข้อมูลที่ไม่ต้องการให้คนทั่วไปเห็น และไม่ควรใส่ข้อมูลผู้ป่วยรายบุคคล
- รายชื่อผู้ใช้และรหัสผ่านแฮช (PBKDF2) อ่านได้เฉพาะซูเปอร์แอดมิน ผู้ใช้ทั่วไปอ่านได้แค่ของตัวเอง
- ควรตั้งรหัสผ่านผู้ใช้ยาวอย่างน้อย 10 ตัว เพราะลองเดารหัสผ่านผ่านลิงก์ได้
- สิทธิ์ที่ฝั่งเซิร์ฟเวอร์แบ่งเป็นระดับกว้าง: ผู้ใช้ที่มีสิทธิ์แก้ไขอย่างน้อยหนึ่งขั้นตอนเขียนรายการได้ การแบ่งละเอียดรายขั้นตอนควบคุมที่หน้าเว็บ

## ข้อมูล
ชีต `records`, `users`, `settings`, `agencies` เก็บข้อมูลเป็น JSON ห้ามแก้ด้วยมือ ควรทำสำเนาสเปรดชีตสำรองเป็นระยะ ระบบซิงก์ข้อมูลทุก ~6 วินาที ถ้าสองคนแก้รายการเดียวกันพร้อมกัน ฉบับที่บันทึกทีหลังจะทับ

## แก้ปัญหา
- **เชื่อมต่อไม่สำเร็จ** ตรวจว่า Deploy เป็น Anyone และ URL ลงท้าย `/exec`
- **ตั้งซูเปอร์แอดมินไม่ได้ (รหัสลับไม่ถูกต้อง)** รหัสต้องตรงกับ `API_KEY` ใน Code.gs ทุกตัวอักษร และต้องยังไม่มีผู้ใช้ในระบบ
- **แก้ Code.gs แล้วไม่เปลี่ยน** ต้อง Deploy เป็น New version
